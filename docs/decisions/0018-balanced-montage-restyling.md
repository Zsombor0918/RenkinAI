# ADR0018 - versioned montage restyling and provisional balanced quality

Date: October19,2026. Status: owner-authorized quality/cost optimization.

## Decision and evidence

The owner reports better style fidelity after Sunburst/high but an approximately
6–7x bill increase. Supplied Samsung screenshots show arbitrary container/literal
logo behavior and dense-screen pixelation, not actual RAW/source dimensions or billing.
The preview decoder's128-versus384 physical-pixel defect is independently reproduced
and corrected. No source sharpening, source substitution or montage downsizing.

Keep the shared automatic montages and one editable brief. New Trial contractV4
shortens fixed drawing guidance and makes IMAGE1 identity rather than a tracing
template. Reconstruct target geometry when supported, do not automatically retain
an original platform badge or apply one charcoal container to every target. Shared
montage construction plus reviewed instructions guide style; no reference identities,
unsupported effects or multiple-icon output. n=1/1024x1024/transparent/PNG stay fixed.
No new analysis stage/schema or endpoint.

Future montage default becomes Sunburst/medium, with the existing Sunburst/high
choice labeled Best quality and medium labeled Balanced under existing Details.
Global AI1/AI2/manual settings remain unchanged. The owner found Sunburst useful;
lowering output quality retains that model, without claiming comparable aesthetics.
The [pricing study](../qa/GENERATION_QUALITY_COST.md) shows identical2.5 token rates,
not guaranteed identical real request cost. Official output estimates439/1756 tokens
imply75% output-only saving, but repeated uncached images limit complete savings.
Actual owner token usage, previous settings and retry counts are unavailable; the
6–7x difference is not reconciled or attributed solely to model selection.

The offline calculator accepts explicit hypothetical input counts, with no network
or keys. It reproduces the official output-estimation formula and normal token
rates. Dollar totals are planning scenarios, not an in-app price guarantee. No
Responses cache discount is incorrectly applied to direct Images edits; migration
would add mainline-model overhead and unproven savings, so keep the endpoint.

## Persistence, privacy and safety

V1/V2/V3 reconstruction and fingerprints remain unchanged, including a fixed V3
text hash. New V4 binds effective text hashes, actual ordered original/montage PNGs
and model/quality before separate paid consent in the existing plan/journal. No
new database or destructive migration; saved editable style text is never overwritten.
Recovery cannot silently replace a frozen quality or upgrade a consumed request.

A focused regression also reveals that V3 profile invalidation creates an unreadable
zero-reference tombstone. Retain one all-zero reference sentinel, matching the existing
Stability strategy, and rehash with the original3/4 version. Keep prepared=false,
rotated epoch, cleared actual image files and consumed UUIDs. This is a local
readability/safety repair, not a replay permission. Both versions are tested.

Tests use synthetic PNGs and loopback HTTP; no owner keys, phone, API call or signing
change. JPEG screenshots stay outside the repository; synthetic quality/request
evidence is retained by the existing CI artifact.

## Alternatives, limits and rollback

Blindly selecting Flare because it is smaller does not demonstrate savings. Shrinking
montages can lose typography/style; increasing bitmap canvases invents no detail.
Neither is adopted. Source resolution remains limited by actual packaged artwork and
Android density selection; without owner APKs, higher native variants are unknown.
The native fixture spans bitmap/text/vector/adaptive/layered artwork and records the
distinction between48 actual bitmap pixels and1024 output pixels.

No new pricing UI, provider, batch engine, active DNA analysis or original-editor
redesign. A separately owner-operated fixed-input Balanced/Best visual comparison
decides practical acceptance/cost; offline success is not visual fidelity. Safe
rollback is a compatible forward repair retaining V4 readers and consumed evidence;
an older V3-only binary cannot read V4 plans. Never erase state to permit downgrade.
