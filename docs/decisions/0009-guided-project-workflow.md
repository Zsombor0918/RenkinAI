# ADR 0009 — presentation over existing project ownership

Date: October 14, 2026. Status: proposed for owner review.

## Context

The owner supplied eight phone screenshots and authorized Stage0/1 guided UX work
from verified PR7 `2f422ca8`, with PR6/main preserved. Parallel aggregate/DNA controls,
duplicate save instructions and raw trial history obscure the existing durable workflow.

## Decision

Present four steps within the existing shell: project/source, style, trials, completion.
The shell owns only navigation. Existing repository metadata owns saved style/targets;
owned controllers and their journals own preparation, paid consent and historical results.
Local draft state may survive navigation but cannot certify persistence or approval.

Fresh DNA-capable projects recommend Quick. Existing aggregate/manual results retain
an explicit Legacy path without automatic conversion or billing. Successful immutable
DNA or manual saves notify the parent only after persistence. A pending child save locks
parent actions. A verified current saved target list hydrates presentation without a write;
changed source/catalog/protection still requires explicit review and existing Save checks.

Current trial cards summarize results by recognizable app; expandable history retains
every variant and endpoint marker. Readiness always considers all current successes,
including an older unreviewed variant concealed under history. Completion reports style
saved, trial review and separate set approval, independently of Apply/build/install.

## Alternatives and consequences

A new database, request coordinator or global lifecycle owner would duplicate established
ownership and is rejected. Hiding historical results to clear warnings would invalidate
review/billing evidence and is rejected. Broad cleanup and fidelity prompt rewrites are
separate Stage2/3 proposals. Existing API-compatible shell consumers remain testable;
the normal app enables the guided presentation using the same underlying repositories.

Windows verification uses the native batch Gradle wrapper; POSIX keeps its original shell
wrapper. The complete runner retains all prior groups/selectors and adds guided journey
coverage, with unchanged XML/skip/error/exit failure conditions. Stacked workflows add
the new PR base without weakening jobs or changing main protection.

Roomv21, tagged DNA readers, backups, immutable assets, original IMAGE1/style-only refs,
consumed markers, legacy clients, app/pack identities and both signing key paths remain.
Green tests never imply device/provider fidelity, signing compatibility or owner acceptance.

Current aggregate/DNA record validity is tracked independently from the latest
operation error. Coalesced cross-profile refreshes are local reads only; obsolete
routes cannot drain a paid preparation or replay. The compact completion status
revalidates locally when an in-flight request finishes and labels unsuccessful
historical items as history rather than current approval failures.

Native Git snapshots normalize CRLF before strict declaration matching. This is an
input normalization decision, not a relaxed impact/PR audit rule. Hook fixtures use
LF matching repository policy; real hook tests and all previous guard assertions remain.
